# MatrixOne BF16 及其向量类型测试设计

> 本设计覆盖 Feature [#20567](https://github.com/matrixorigin/matrixone/issues/20567)：新增 BF16（bfloat16）标量数据类型及其对应的向量、稀疏向量等类型。BF16 是对 float32 的截短格式，语义和精度特征均不同于 IEEE float16，测试不得用 float16 行为替代 BF16 验证。

## 1. 测试原则

| 项目 | 说明 |
| --- | --- |
| 类型语义优先 | 以 BF16 的格式、舍入、范围、特殊值和转换语义为核心；必须与 float16 建立差异对照。 |
| 端到端覆盖 | 覆盖 SQL parser/binder、DDL、DML、表达式、函数、执行器、存储、导入导出、驱动和恢复链路。 |
| 数值判定 | 精确可表示值按位/文本等价；非精确值按 BF16 舍入后的 f32 基线和 epsilon 判定，不能直接要求等于原始 f32。 |
| 容器一致性 | 向量/稀疏向量的数据维度、元素类型、NULL、索引和值顺序必须在插入、查询、函数和持久化后保持一致。 |
| 兼容性 | 已有 float32/float64/float16 与向量功能不回归；混合类型规则必须明确，禁止静默窄化导致不可解释的数据损失。 |
| 异常可诊断 | 非法字面量、维度、稀疏索引、溢出和不支持的操作必须明确报错，不得 panic 或写入部分数据。 |

### 1.1 基本信息

| 项目 | 内容 |
| --- | --- |
| MatrixOne 基线 | `main`（Feature #20567） |
| 标量类型 | BF16 / `bfloat16`（最终 SQL 关键字以实现为准） |
| 容器类型 | BF16 向量（如 `VECBF16(d)`）及 BF16 稀疏向量（最终类型名/字面量以实现为准） |
| 核心区别 | BF16 保留 float32 的符号位和 8 位指数、缩短尾数；与 float16 的指数/尾数分配、范围和精度不同。 |
| 主要风险 | 舍入错误、NaN/Inf 处理不一致、跨类型隐式转换、向量维度/稀疏索引错误、序列化丢失和存储恢复错位。 |

## 3. 基线与结果判定

### 3.1 BF16 数值基线

1. 使用可信 BF16 reference（或将值按规定 BF16 rounding 后扩展为 float32）生成期望值；原始 float32 仅作为输入基线。
2. 可精确表示值必须完全相等；非精确值以绝对/相对 epsilon 比较，并记录原值、BF16 位模式（若可见）、期望 f32、实际值。
3. 对 BF16 与 float16 使用相同样本集，至少覆盖指数范围、尾数精度和上/下溢边界，确认类型差异。

### 3.2 向量/稀疏基线

| 场景 | 基线 |
| --- | --- |
| 稠密 BF16 向量 | 将每个元素按 BF16 舍入后，以 f32 实现同一函数/距离，比较结果。 |
| 稀疏 BF16 向量 | 展开为相同逻辑维度的稠密 BF16 向量后计算；索引和值必须一一对应。 |
| 向量检索 | 使用全表精确距离和稳定 PK 排序核对 Top-K；近似索引另记录 Recall@K。 |
| 导入/恢复 | 比较 schema、NULL、维度、元素及 BF16 舍入后数值，而非原始输入 f32。 |
